API server.js — Mell Footage

Полная документация REST API сайта футажей. Сервер: Node.js + Express, БД — SQLite (WAL). Аутентификация — сессии (cookie). Всего эндпоинтов: —.

00Базовая информация

Базовый URL
http(s)://<host> — порт из PORT (по умолчанию 80)
Формат данных
JSON (application/json), лимит тела — 10 МБ. Загрузки файлов — multipart/form-data
Аутентификация
Session-cookie (express-session, хранилище SQLite sessions.db): httpOnly, sameSite=lax, secure в production, срок 7 дней. Роль и верификация перечитываются из БД на каждый запрос; обновляется last_seen
Регистрация по email
в отдельном модуле mail-auth.js (mountMailAuth) — коды через Resend
Комнаты-чаты
в отдельном модуле rooms.js (mountRooms): /rooms, /room/:id, /api/rooms/*
Безопасность
helmet (CSP, HSTS, noSniff, frameguard), CORS-белый список (localhost / 192.168.x.x), санитизация ввода (удаление <> и javascript:), проверка путей (isPathInside) против path traversal

02Ошибки и лимиты

Формат ошибок

Все ошибки — JSON: { "error": "текст" }. Глобальный обработчик гарантирует JSON даже при сбоях Multer / CORS.

КодКогда
400невалидные данные, лимиты (коллекций — 6, заявок — 5/день, имя файла занято)
401нет сессии («Нужно войти»), пользователь не найден
403нет прав (роль), бан аккаунта, приватная коллекция, доступ к сессии при 2FA
404файл/пользователь/коллекция не найдены
409логин занят, тег уже выдан
416некорректный Range при стриминге
429rate limit

Rate limits (express-rate-limit)

  • Общий — на все /api/*: окно 3 минуты (стрим аудио /stream исключён, статика не считается).
  • authLimiter — /api/login, /api/register/*: 30 попыток за 15 минут, успешные не считаются.

Лимиты загрузок

  • Видео (админ): mp4, mkv, webm, mov, до 100 МБ.
  • Заявки на футажи: только видео, до 7 МБ, максимум 5 в день на пользователя.
  • Аватар: png, jpg, jpeg, webp, до 5 МБ (заблокированным менять нельзя).
  • Картинки новостей: png, jpg, jpeg, webp.

03Футажи и медиа

Каталог одобренных футажей, стриминг с поддержкой Range-запросов и превью через ffmpeg.

GET/api/videosпубличный

Список всех видео в папке videos/ (новые первыми), с автором из одобренных заявок.

Ответ (элемент массива)
{
  "id": "myclip",
  "name": "myclip.mp4",
  "url": "https://host/videos/myclip.mp4",
  "uploader": {
    "username": "nick", "role": "user",
    "is_verified": false,
    "avatar_url": "/uploads/avatars/1_x.png",
    "activity_visible": true,
    "last_seen": "2026-10-01T12:00:00.000Z",
    "tags": [{ "id": 1, "name": "OG", "color": "#7ec384", "icon": "👑" }]
  }
}
uploader: null — если видео добавлено админом напрямую, а не через заявку.
GET/videos/:filenameпубличный

Отдаёт видео (mp4, mkv, webm, mov) и изображения с поддержкой Range (HTTP 206). Имя файла защищено от path traversal, тип проверяется по белому списку. Заголовки: Accept-Ranges, Cache-Control: public, max-age=3600. Некорректный Range → 416 с Content-Range: bytes */size.

GET/api/thumb/:filenameпубличный

JPEG-превью видео (кадр после 1 сек, ширина 480px). Генерация через ffmpeg-static — по очереди, по одной задаче. Если ffmpeg не установлен или кадр не извлечён — 404. Результат кэшируется в public/uploads/thumbs/.

POST/admin/uploadadmin, senior_moderator

Прямая загрузка футажа в videos/. multipart/form-data, поле videoFile; типы: mp4, mkv, webm, mov; до 100 МБ. Имя берётся из поля nameof (или оригинала), санитизируется, до 100 символов.

Ответ
{ "success": true, "filename": "myclip.mp4" }

10Заявки на футажи

Пользователь присылает футаж на модерацию; после одобрения файл переезжает в videos/ и попадает в каталог.

POST/api/submissionsнужен вход

multipart/form-data: поле video (только видео, ≤ 7 МБ), текстовое поле display_name (название, ≤ 100). Файл сохраняется в submissions/ с префиксом sub_<timestamp>_<user_id>.

Ответ
{ "success": true }
Ограничения: максимум 5 заявок в день на пользователя; заблокированным отправка запрещена (403); файл при ошибке удаляется с диска.
GET/api/submissions/myнужен вход

Свои заявки: id, display_name, status (pending | approved | rejected), created_at.

GET/api/admin/submissionsмодератор+

Заявки со статусом pending (старые первыми), с ником отправителя.

POST/api/admin/submissions/:id/approveмодератор+

Переносит файл из submissions/ в videos/ под финальным именем (название можно переопределить в display_name, санитизация + только буквы/цифры/_/-/пробелы). Обновляет запись, ставит broadcast- и личное уведомления. Требуется SITE_URL в .env для ссылок.

Запрос (тело опционально)
{ "display_name": "Клип 2026" }
Ответ
{ "success": true }
POST/api/admin/submissions/:id/rejectмодератор+

Удаляет файл с диска, ставит статус rejected, отправляет автору личное уведомление. Тело не нужно.

12Вход и регистрация

Регистрация и восстановление пароля по email (Resend) живут в модуле mail-auth.js. Ниже — эндпоинты из server.js. Все защищены authLimiter.

POST/api/loginauthLimiter
Запрос
{ "username": "nick", "password": "secret" }
Ответ
{
  "success": true,
  "user": { "id": 1, "username": "nick",
    "role": "user", "is_verified": false,
    "telegram_linked": false }
}
400 — неверный логин/пароль · 403 — аккаунт заблокирован: { "error": "Аккаунт заблокирован", "reason": "...", "until": "..." }. При входе сессия регенерируется (защита от session fixation).
POST/api/logoutбез прав

Уничтожает сессию. Ответ: { "success": true }.

GET/api/meпубличный
Ответ
{ "loggedIn": true, "user": { "id": 1, "username": "nick", "role": "user", "is_verified": false, "telegram_linked": false } }

Гость: { "loggedIn": false }. Роль и верификация в сессии актуализируются из БД на каждый запрос.

POST/api/register/startauthLimiter

Устаревший флоу регистрации с подтверждением через Telegram. Проверяет логин (/^[a-zA-Z0-9_\-]{3,15}$/, не из RESERVED_USERNAMES: admin, moder, moderator, root, system, support), пароль ≥ 6 симв., Telegram ID (5–15 цифр) и accept_terms === true. Код (6 цифр, TTL 10 мин) уходит боту; подтверждение — POST /api/register/confirm с { "code": "123456" }.

Фронтенд сейчас использует регистрацию по email из mail-auth.js.
POST/api/register/confirmauthLimiter

Проверяет код из Telegram, создаёт аккаунт (роль user, фиксируется terms_accepted_at и версия условий) и привязывает telegram_users. Ошибки: код истёк / неверный / логин или Telegram заняты.
